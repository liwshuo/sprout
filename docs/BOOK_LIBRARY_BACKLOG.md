# 共建书库 后续 Backlog（P1 / P2 / 技术债）

> 本文档记录「共建书库」在 P0（书库基础可用）之后的迭代待办。P0 范围与最终确认任务清单见 `docs/PRODUCT_SPEC.md` 与最新一轮 Review 结论。
> 约定：功能落地后，同步勾销本文件对应项，并更新 `docs/PRODUCT_SPEC.md` 与 `CHANGELOG.md`。
>
> 优先级说明：
> - **P1**：有了初始用户后实施（书库已有一定内容、用户开始沉淀行为）。
> - **P2**：数据量和用户量足够后实施（书库总量、注册用户、行为数据达到规模）。

---

## P1（有了初始用户后实施）

- [ ] **用户提交书到共建书库**：在扫码录入流程末尾挂载「分享到书库」引导（扫码确认弹层保存成功后，追加一步「同步分享到共建书库」的可选引导），把用户录入的书沉淀为共建内容。
- [ ] **点赞 / 推荐功能**：`book_library.likeCount`（计数）+ `book_library.likedBy[]`（去重用户列表），内嵌于书库文档；单书点赞超过 100 条后拆独立 `book_likes` 集合承接（见技术债）。
- [ ] **`addCount` 统计**：加入书架时对 `book_library.addCount` +1，从书架删除该书时 -1，作为「被加入次数」热度基础指标。
- [ ] **`readFinishCount` 统计**：打卡完成最后一页 / 最后一章（触发书籍 `status → done`）时对 `book_library.readFinishCount` +1，前端直接 `inc`。
- [ ] **完读率展示**：`readFinishCount / addCount`，在书卡上展示（如「完读率 62%」），帮助家长判断书是否读得下去。
- [ ] **书库开放阈值**：书库总量 < 50 本 **或** 注册用户 < 100 人时，隐藏热度相关 UI（点赞数、完读率、热度榜入口），避免冷启动阶段数据过于稀疏而显得空洞。

---

## P2（数据量和用户量足够后实施）

- [ ] **热度榜**：榜单形式，固定 Top N；只统计最近 30 天行为，引入时间衰减（近期行为权重更高），避免老书长期霸榜。
- [ ] **想读清单**：`books.status` 字段支持 `wishlist | reading | finished`（对齐现有 `want/reading/done` 语义，需统一口径），书架新增「想读」Tab。
- [ ] **章节书支持**：`book_library.type: "chapter_book"`，`chapters[]` 章节列表内嵌；`reading_logs.chapterIndex` 已存在，作为可选字段承接章节打卡粒度。
- [ ] **搜索优化**：当前为前端内存搜索；数据量变大后考虑服务端搜索或倒排索引（云函数 + 关键词索引集合）。
- [ ] **封面转存云存储**：当前用 `coverExternalUrl` 外链，稳定后可批量转存到云存储（防外链失效、加速加载），保留 `coverExternalUrl` 作为兜底。
- [ ] **分册独立 uuid**：`book_library.volumes[]` 每项新增 `uuid`；`reading_logs.volumeUuid` 作为可选字段，支持分册粒度的热度 / 完读统计。
- [ ] **书库版本号 + 缓存失效机制**：`app_config.libraryVersion`（书库整体版本号），客户端本地缓存书库快照，启动时对比版本号决定是否刷新缓存，降低冷启动请求量。
- [ ] **扫码冷启动优化**：`bookLookup` 云函数预热（定时触发保活）+ ISBN 本地缓存（命中过的 ISBN 直接读本地，减少重复查询）。
- [ ] **年龄段智能推荐**：根据当前孩子年龄段（由 `children.birthDate` 派生）自动过滤书库默认展示的年龄段 Tab。
- [ ] **贡献者成就感设计**：如「你录入的书帮助了 XX 个同龄孩子的家长」，把贡献行为转成正反馈，激励持续共建。

## 技术债记录

- [ ] **`addCount` 并发 inc 风险**：多用户同时加入 / 删除同一本书时，`inc` 存在并发写竞争。早期用户量可控可接受；用户量上来后考虑消息队列削峰或批量写入（定时聚合）。
- [ ] **`likedBy[]` 文档体积上限**：CloudBase 单文档上限 512KB，`likedBy[]` 存 openid 数组约 1.5 万点赞即触顶；届时拆独立 `book_likes` 集合（一行一个 `{ bookUuid, userId }`），`likeCount` 保留在主文档做展示。
- [ ] **前端内存搜索体积上限**：书库超 500 本时，全量缓存到本地可能超小程序 storage 单 key 1MB 限制；届时只缓存轻量字段（`uuid/title/author/ageRange/type`），详情按需拉取。
